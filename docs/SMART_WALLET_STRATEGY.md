## 2. 策略概述

### 2.1 跟单策略 (Copy Strategy)

**核心逻辑**: 当高评分钱包以低价买入时，我们跟随买入。

```
信号条件:
1. 钱包 composite_score ≥ 0.6
2. 交易 side = BUY
3. 交易金额 ≥ $50
4. 入场价格 ≤ 0.80
5. 冷却期: 同一市场 30 分钟内不重复交易

仓位管理:
- 使用 Kelly 准则的 1/4 分数
- 单笔最大 2% 资金
- 最多 20 个并发仓位
- 止损: -30%
- 止盈: +50%
```

**为什么只跟买单?**
- 卖单原因不明确（止盈? 清仓? 信心下降?）
- 买单信号更清晰：钱包认为价格会涨

### 2.2 逆向策略 (Inverse Strategy)

**核心逻辑**: 当聪明钱包在高价 (>0.60) 买入时，市场已充分定价，我们反向交易。

```
信号条件:
1. 钱包 composite_score ≥ 0.6
2. 交易 side = BUY
3. 入场价格 ≥ 0.60 (关键差异!)
4. 交易金额 ≥ $100
5. 冷却期: 同一市场 60 分钟

仓位管理:
- 使用 Kelly 准则的 1/8 分数 (更保守)
- 单笔最大 1% 资金
- 止损: -25%
- 止盈: +40%
```

**逆向策略的逻辑基础**:
- Polyloly 数据显示: 入场价格 > 0.65 的信号胜率下降至 ~60%
- Convexly 研究: 高价入场通常是"迟到的聪明钱"
- 逆向不是"反对聪明钱"，而是"反对迟到的聪明钱"

### 2.3 智能钱包评分体系

| 权重 | 指标 | 说明 |
|------|------|------|
| 40% | 胜率 | 已结算市场的 PnL > 0 的比例 |
| 30% | 交易量 | 对数归一化 (log₁₀(Volume)/6) |
| 30% | 边际收益 | Sharpe-like 指标，衡量每笔交易的超额收益 |

**最低入选标准**:
- 至少 10 笔已结算交易
- 总投入 ≥ $5,000
- 胜率 ≥ 70%

## 4. 研究证据链

### 4.1 核心证据 #1: Polyloly 回测研究

**来源**: https://polyloly.com/blog/polymarket-insider-tail-backtest-46-percent-roi

**关键数据点**:
| 指标 | 数值 | 说明 |
|------|------|------|
| 总交易数 | 334 笔 | 纸面交易回测 |
| 胜率 | 75.9% | 仅入场 < 0.65 的信号 |
| ROI (零滑点) | +46.7% | 纯信号价值 |
| ROI (3¢滑点) | +15-25% | 含实际成本 |
| 最优进场 | < 0.65 | 高于此价格胜率下降 |
| 最差进场 | > 0.80 | 高于此价格基本无 Alpha |

**方法论验证**:
- 使用了"insider-tail"方法 — 跟踪钱包而非交易
- 仅跟踪 BUY 信号 (卖出原因不明确)
- 按钱包累计 PnL 排名，过滤噪音

**局限性**:
- 纸面交易，非实际执行
- 样本期可能偏短
- 未考虑流动性冲击

### 4.2 核心证据 #2: Convexly 10,000 钱包研究

**来源**: https://www.convexly.app/blog/polymarket-10k-wallet-study

**关键发现**:
1. **校准度几乎不预测利润** — 钱包的"自信程度"与实际收益相关性很低
2. **利润高度集中** — 前 1% 的钱包捕获 36.2% 的总利润
3. **持续性存在** — 高分钱包在后续交易中保持较高胜率
4. **入场价格是关键** — 低于 0.60 入场的信号显著优于高于 0.60 的

**对策略的启示**:
- 不要盲目跟单"自信的"钱包，要跟"赚钱的"钱包
- 逆向策略应该只在高入场价格时使用
- 钱包筛选标准应该基于实际 PnL 而非交易频率

### 4.3 核心证据 #3: Alpha Edge 研究

**来源**: https://alphaedge.io/blog/copy-trading-polymarket-75-percent-win-rate

**关键数据**:

## 5. 回测框架

### 5.1 框架特性

| 特性 | 实现 | 说明 |
|------|------|------|
| **事件驱动** | ✅ | 逐笔信号处理，无前瞻偏差 |
| **滑点模型** | ✅ | 基础滑点 + 交易量冲击 + 随机噪声 |
| **延迟模型** | ✅ | 信号延迟 + 网络延迟 + 价格漂移 |
| **费用模型** | ✅ | Taker 费 30 bps |
| **样本外验证** | ✅ | 70/30 时间序列分割 |
| **Walk-forward** | ✅ | 滚动窗口分析 |
| **Monte Carlo** | ✅ | 1000 次模拟，置信区间 |

### 5.2 滑点模型详解

```python
total_slippage_bps = (
    base_slippage_bps        # 15 bps — 流动性充足的市场
    + spread_bps             # 5 bps — 买卖价差
    + volume_impact          # 0.1 bps per $1000 traded
    + random_noise           # ±5 bps 随机波动
)

# 上限: 100 bps (1%)
```

**参数校准依据**:
- **基础滑点 15 bps**: 来自 Polyloly 使用的 3¢ 滑点假设 (约 15-30 bps 取决于价格)
- **买卖价差 5 bps**: 来自 Polymarket 订单簿实际观测
- **交易量冲击**: 经验公式，大单会推高价格

### 5.3 延迟模型详解

```python
total_latency_s = (
    signal_delay_min_s       # 2-5 秒 — 从钱包交易到我们检测到
    + network_latency_min_s  # 1-3 秒 — 从检测到订单到达
)

# 总延迟: 3-8 秒
# 价格漂移: ~2 bps/秒 (市场波动期间)
```

**参数校准依据**:
- **信号延迟 2-5 秒**: Polymarket Data API 轮询间隔 + API 响应时间
- **网络延迟 1-3 秒**: 到 Polymarket CLOB 的网络延迟
- **价格漂移 2 bps/秒**: 来自 Convexly 的市场微观结构研究

### 5.4 回测执行流程

```
输入信号列表 (按时间排序)
    │
    ▼
┌─────────────────────────────────────┐
│ 对每个信号:                          │
│ 1. 检查时间范围                       │
│ 2. 模拟延迟 (随机 3-8 秒)            │
│ 3. 计算执行时价格 (含漂移)            │
│ 4. 应用滑点 (15 bps + 交易量冲击)    │
│ 5. 计算费用 (30 bps)                 │
│ 6. 检查资金是否充足                   │
│ 7. 检查仓位上限                       │
│ 8. 开仓                             │
└─────────────────────────────────────┘
    │
    ▼
对每个持仓:
    检查止损/止盈/到期
    │
    ▼
计算绩效指标
```

| 滑点 (15 bps) | $50 × 0.0015 | $0.075 |
| 买卖价差 (5 bps) | $50 × 0.0005 | $0.025 |
| 交易量冲击 | ~$0.005 | $0.005 |
| Taker 费 (30 bps) | $50 × 0.003 | $0.150 |
| **总成本** | | **$0.255** |
| **成本率** | | **0.51%** |

### 6.2 需要多少 Alpha 才能盈利?

### 7.1 风险矩阵

| 风险 | 概率 | 影响 | 缓解措施 |
