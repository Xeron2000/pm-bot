# Research: Polymarket CLOB Trading

- **Query**: How to place orders programmatically on Polymarket CLOB (order types, authentication, API keys, order book structure)
- **Scope**: External

## Findings

### CLOB Architecture

Polymarket's CLOB (Central Limit Order Book) is a **hybrid-decentralized trading system**:
- **Offchain**: Order matching happens on the CLOB server
- **Onchain**: Matched trades settle atomically on Polygon via the Exchange contract
- **Non-custodial**: The operator cannot set prices or execute unauthorized trades
- Orders are **EIP-712 signed messages** -- the signature authorizes the Exchange contract to trade on your behalf without custody

### Authentication (Two-Level System)

#### L1 Authentication -- Private Key (EIP-712)

**Purpose:** Create or derive API credentials. Proves ownership of the private key.

**Required headers:**

| Header | Description |
|---|---|
| `POLY_ADDRESS` | Polygon signer address |
| `POLY_SIGNATURE` | CLOB EIP-712 signature |
| `POLY_TIMESTAMP` | Current UNIX timestamp |
| `POLY_NONCE` | Nonce (default: 0) |

**EIP-712 signed struct:**
The `POLY_SIGNATURE` is generated by signing an EIP-712 typed data struct. The SDK handles this automatically.

#### L2 Authentication -- HMAC-SHA256 (API Credentials)

**Purpose:** Place orders, cancel orders, query trades. All trading endpoints require L2.

**Required headers (5 total):**

| Header | Description |
|---|---|
| `POLY_ADDRESS` | Polygon signer address |
| `POLY_SIGNATURE` | HMAC-SHA256 signature of the request |
| `POLY_TIMESTAMP` | Current UNIX timestamp |
| `POLY_API_KEY` | User's API `apiKey` value |
| `POLY_PASSPHRASE` | User's API `passphrase` value |

**HMAC signature:** Created using the API credential's `secret` value. The SDK handles this automatically.

**Critical note:** Even with L2 authentication, methods that create orders still require the user's private key for EIP-712 order payload signing. L2 authenticates the request; the order itself must be signed by the key.

### API Credential Derivation Flow

```python
# Python V2 SDK
from py_clob_client_v2 import ClobClient, ApiCreds

# Step 1: Create client with private key only (L1 auth)
client = ClobClient(host="https://clob.polymarket.com", chain_id=137, key=PRIVATE_KEY)

# Step 2: Create or derive API credentials
creds = client.create_or_derive_api_key()
# Returns: ApiCreds(api_key=..., api_secret=..., api_passphrase=...)

# Step 3: Initialize fully-authenticated client (L1 + L2)
client = ClobClient(
    host="https://clob.polymarket.com",
    chain_id=137,
    key=PRIVATE_KEY,
    creds=creds,
)
```

```typescript
// TypeScript V2 SDK
import { ClobClient } from "@polymarket/clob-client-v2";

const tempClient = new ClobClient({ host: "https://clob.polymarket.com", chain: 137, signer });
const apiCreds = await tempClient.createOrDeriveApiKey();

const client = new ClobClient({
  host: "https://clob.polymarket.com",
  chain: 137,
  signer,
  creds: apiCreds,
});
```

**Important:** Each wallet can only have one active API key at a time. Creating a new key invalidates the previous one. Always use `createOrDeriveApiKey()` (not `createApiKey()`) to avoid invalidating existing credentials.

### Signature Types

| Type | Value | Description | Use Case |
|---|---|---|---|
| EOA | 0 | Browser wallet pays its own gas, acts as funder | Direct wallet users |
| POLY_PROXY | 1 | Polymarket.com account (email/Magic login) | Most common for web users |
| GNOSIS_SAFE | 2 | Gnosis Safe / proxy wallet | Institutional / multi-sig |
| POLY_PROXY | 3 | Another proxy variant | Special cases |

**For POLY_PROXY (type 1) or GNOSIS_SAFE (type 2):**
- Must specify `funder` / `funderAddress` (the proxy wallet address holding funds)
- Proxy wallet users can use Polymarket's gasless relayer instead of paying gas

### Order Types

| Type | Name | Behavior | Category | Use Case |
|---|---|---|---|---|
| **GTC** | Good-Til-Cancelled | Rests on book until filled or cancelled | Limit | Default for limit orders, passive quoting |
| **GTD** | Good-Til-Date | Active until specified expiration time, then auto-expires | Limit | Time-limited orders, expire before known events |
| **FOK** | Fill-Or-Kill | Must fill immediately and entirely, or cancel completely | Market | All-or-nothing execution |
| **FAK** | Fill-And-Kill | Fills what's available immediately, cancels remainder | Market | Partial-fill market orders |

**Key distinctions:**
- GTC and GTD are **limit order types** -- they rest on the book at your specified price
- FOK and FAK are **market order types** -- they execute against resting liquidity immediately
- BUY orders: specify the **dollar amount** you want to spend
- SELL orders: specify the **number of shares** you want to sell

**Post-Only orders:**
- Only works with GTC and GTD order types
- Rejected if combined with FOK or FAK
- Ensures order only adds liquidity (doesn't cross the spread)

### Order Structure

**Order payload fields:**

| Field | Type | Description |
|---|---|---|
| `maker` | address | Maker address |
| `signer` | address | Signer address |
| `tokenId` | string | ERC1155 token ID for the outcome |
| `makerAmount` | string | Amount in token's smallest unit (maker side) |
| `takerAmount` | string | Amount in token's smallest unit (taker side) |
| `side` | string | BUY or SELL |
| `expiration` | string | Expiration timestamp (0 for GTC, UTC seconds for GTD) |
| `timestamp` | string | Order creation timestamp in milliseconds |

**CLOB V2 EIP-712 signed struct uses:** `timestamp`, `metadata`, `builder` (not the V1 fields `expiration`, `nonce`, `feeRateBps`, `taker`)

**Every order requires two market-specific options:**
1. `tickSize` -- Minimum price increment (e.g., "0.01", "0.001"). Get via `getTickSize()` or market data.
2. `negRisk` -- Whether market is negative risk (multi-outcome). Get via `getNegRisk()` or market data. **Weather markets are typically `negRisk=true`**.

### Placing Orders (Python V2 SDK)

```python
from py_clob_client_v2 import ClobClient, OrderArgs, OrderType, Side, PartialCreateOrderOptions

# Limit buy (GTC)
resp = client.create_and_post_order(
    order_args=OrderArgs(
        token_id="0x...",  # from market data
        price=0.4,
        side=Side.BUY,
        size=100,
    ),
    options=PartialCreateOrderOptions(tick_size="0.01"),
    order_type=OrderType.GTC,
)

# Time-limited order (GTD) - expires in 1 hour
resp = client.create_and_post_order(
    order_args=OrderArgs(
        token_id="0x...",
        price=0.35,
        side=Side.BUY,
        size=50,
        expiration=int(time.time()) + 3600,
    ),
    options=PartialCreateOrderOptions(tick_size="0.01"),
    order_type=OrderType.GTD,
)

# Market order (FOK)
from py_clob_client_v2 import MarketOrderArgs
resp = client.create_and_post_market_order(
    market_order_args=MarketOrderArgs(
        token_id="0x...",
        side=Side.BUY,
        size=100,
    ),
    options=PartialCreateOrderOptions(tick_size="0.01"),
    order_type=OrderType.FOK,
)
```

### Placing Orders (TypeScript V2 SDK)

```typescript
import { ClobClient, Side, OrderType } from "@polymarket/clob-client-v2";

// Limit buy (GTC)
const response = await client.createAndPostOrder(
  { tokenID: "YOUR_TOKEN_ID", price: 0.5, size: 10, side: Side.BUY },
  { tickSize: "0.01", negRisk: false },
  OrderType.GTC,
);

// GTD order - expires in 1 hour
const expiringOrder = await client.createAndPostOrder(
  { tokenID: "YOUR_TOKEN_ID", price: 0.5, size: 1000, side: Side.BUY,
    expiration: Math.floor(Date.now() / 1000) + 3600 },
  undefined,
  OrderType.GTD,
);

// Market order (FAK)
const marketResponse = await client.createAndPostMarketOrder(
  { tokenID: "YOUR_TOKEN_ID", side: Side.BUY, size: 10 },
  { tickSize: "0.01" },
  OrderType.FAK,
);
```

### Batch Orders

Up to 15 pre-signed orders can be submitted in a single batch:
```python
# Sign multiple orders locally first
order1 = client.create_order(OrderArgs(...))
order2 = client.create_order(OrderArgs(...))
# Then batch submit
client.post_orders([order1, order2], OrderType.GTC)
```

### Order Management (L2 Methods)

| Method | Description |
|---|---|
| `createAndPostOrder` | Create, sign, and post a limit order in one call |
| `createAndPostMarketOrder` | Create, sign, and post a market order in one call |
| `postOrder` | Post a pre-signed order |
| `postOrders` | Post up to 15 pre-signed orders in batch |
| `cancelOrder` | Cancel a single order |
| `cancelOrders` | Cancel multiple orders |
| `cancelAll` | Cancel all open orders |
| `getOpenOrders` | View all open orders |
| `getTrades` | View trade history |
| `getOrder` | Get a single order by ID |

### Order Book Structure

**Reading the orderbook (public, no auth):**

| Endpoint | Returns |
|---|---|
| `getOrderBook(tokenID)` | Full book with `bids[]` and `asks[]` arrays |
| `getPrice(tokenID, side)` | Best available price for buying/selling |
| `getMidpoint(tokenID)` | Average of best bid and best ask (displayed as implied probability) |
| `getSpread(tokenID)` | Difference between best bid and best ask |
| `getPricesHistory(tokenID)` | Historical price data |
| `getLastTradePrice(tokenID)` | Last executed trade price |

**Batch variants** exist for fetching data across multiple tokens (up to 500):
- `getOrderBooks(BookParams[])`
- `getPrices(BookParams[])`
- `getMidpoints(BookParams[])`
- `getSpreads(BookParams[])`

**WebSocket real-time events:**

| Event | Trigger | Key Fields |
|---|---|---|
| `book` | On subscribe + trade affects book | `bids[]`, `asks[]`, `hash`, `timestamp` |
| `price_change` | New order placed or cancelled | `price_changes[]` with `price`, `size`, `side` |
| `last_trade_price` | Trade executed | `price`, `side`, `size`, `fee_rate_bps` |
| `tick_size_change` | Price hits >0.96 or <0.04 | `old_tick_size`, `new_tick_size` |
| `best_bid_ask` | Top-of-book changes | `best_bid`, `best_ask`, `spread` |
| `new_market` | Market created | `question`, `assets_ids`, `outcomes` |
| `market_resolved` | Market resolved | `winning_asset_id`, `winning_outcome` |

### Pre-Trade Requirements

Before placing orders, ensure:

| Requirement | Description |
|---|---|
| **Balance** | Sufficient pUSD (for buys) or outcome tokens (for sells) |
| **Allowance** | Approve the Exchange contract to spend your assets |
| **API Credentials** | Valid API key (L2 authentication) |
| **Funder Address** | Correct for your wallet type (EOA = your address; proxy = proxy wallet address) |
| **Signature Type** | Matches your account type (0/1/2/3) |
| **Tick Size** | Must match market's tick size (get via `getTickSize()`) |
| **Neg Risk** | Must match market's neg risk flag (weather markets = true) |

### REST API Direct Usage (Without SDK)

If using the REST API directly (not recommended), you must:
1. Sign EIP-712 messages for L1 auth and order payloads
2. Generate HMAC-SHA256 signatures for L2 request headers
3. Construct all 5 POLY_* headers per request
4. Handle nonce management

Reference implementations are in the TypeScript and Python SDK source code.

## Caveats / Not Found

- The Exchange contract address and ABI are not documented in the API docs; they would be needed for direct onchain interaction or approval transactions
- The exact pUSD (Polygon USDC) approval flow is not fully detailed in the API docs; the SDK likely handles this
- Gasless relayer endpoint and documentation for proxy wallet types (1/2) is not explicitly shown in search results
- The CLOB V2 EIP-712 struct has changed from V1 (no more `nonce`, `feeRateBps`, `taker` in signed struct); V1 and V2 SDKs are not interchangeable
- Weather markets require `negRisk=true` in order options; failing to set this will cause order rejection
- Batch order submission (up to 15) is useful for placing orders across multiple temperature buckets simultaneously
- The WebSocket API URL is not explicitly documented in search results but is likely at `wss://clob.polymarket.com/ws`
